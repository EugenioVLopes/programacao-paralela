Lição 04: Limites de memória e CPU com OpenMP

Tarefa 04 • Dissecção de tarefa04.c • O gargalo de von Neumann e saturação de barramento

1. O gargalo de von Neumann

Na computação de alto desempenho, o processador e a memória principal residem em chips distintos. A comunicação entre eles ocorre através de um barramento que possui um limite máximo de banda (medido em GB/s).

  • Memory-bound: Quando a CPU é rápida o suficiente para que a aplicação sature a leitura de dados da memória, o gargalo se move para o barramento. A CPU passa a maior parte do tempo ociosa esperando a chegada da informação (gargalo de von Neumann).
  • CPU-bound: Quando a aplicação calcula valores de forma intensa reutilizando poucos dados armazenados nas caches próximas (L1/L2), o gargalo é o próprio poder de processamento da ALU.

A paralelização multi-thread tem impactos radicalmente distintos nesses dois perfis.

2. Dissecção linha a linha de tarefa04.c

1. Teste memory-bound (soma de vetores)

#pragma omp parallel for
for (long i = 0; i < n; ++i) {
    C[i] = A[i] + B[i];
}
  • #pragma omp parallel for: Instrui o OpenMP a gerar uma equipe de threads e dividir o laço entre elas (ex: se 4 threads operam sobre $1000$ elementos, cada uma pega $250$).
  • A intensidade aritmética é baixíssima: executa-se apenas 1 FLOP (uma adição) para cada 3 acessos à memória (leitura de A e B, escrita de C).
  • O gargalo será rapidamente deslocado para o barramento de memória, fazendo com que o aumento de threads eventualmente deixe de gerar aceleração.

2. Teste CPU-bound (operações transcendentes)

#pragma omp parallel for
for (long i = 0; i < n; ++i) {
    double val = V[i];
    for (int j = 0; j < 50; ++j) {
        val = sqrt(val + j * 0.01) + sin(val);
    }
    V[i] = val;
}
  • Esta estrutura lê 1 valor V[i] da memória para um registrador local (val).
  • Em seguida, submete este registrador a 50 laços de operações pesadíssimas no nível do hardware da ALU (sqrt e sin).
  • Só após muita computação (alta intensidade aritmética), o resultado é salvo novamente na memória principal. O limitante absoluto é o clock da CPU. Adicionar threads gerará escalabilidade ideal.

3. O efeito do hardware multithreading

Muitas CPUs modernas oferecem SMT (Simultaneous Multithreading, ou Hyper-threading na Intel). Eles dobram o número de núcleos lógicos apresentados ao sistema operacional, mas sem dobrar as unidades físicas de execução (ALUs, FPUs).

  • Ajudando no CPU-bound: Em programas computacionalmente intensos, se uma thread lógica trava esperando uma instrução, a outra thread lógica no mesmo núcleo físico pode preencher o pipeline e executar computação, aumentando o throughput global.
  • Atrapalhando no Memory-bound: SMT agrava a competição. As threads extras geram ainda mais tráfego na cache e no controlador de barramento, exaurindo a largura de banda. Nestes casos, usar todas as threads lógicas costuma ser mais lento que usar apenas as threads físicas.

4. Quizzes interativos

Questão 1 de 2
O que define o gargalo de von Neumann (memory wall) nas arquiteturas de alto desempenho atuais?
Correto! Devido ao fosso tecnológico, as CPUs processam dados muito mais rapidamente do que os barramentos de memória DRAM conseguem transferir, mantendo a CPU faminta por dados.
Questão 2 de 2
Por que a adição de mais threads via SMT (Hardware Multithreading) frequentemente piora o desempenho de programas do tipo memory-bound?
Correto! Como as threads competem ativamente pelo mesmo recurso gargalo (largura de banda da memória) que já estava saturado pelos núcleos físicos, o tráfego gerado pela contenção causa atrasos extremos para todos.
