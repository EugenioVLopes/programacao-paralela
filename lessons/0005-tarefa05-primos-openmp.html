Lição 05: Race Conditions e Loop Parallelism

Tarefa 05 • Dissecção de tarefa05.c • O perigo do estado compartilhado

1. O Teste de Primalidade e a Natureza do Laço

O programa conta primos no intervalo $[2, N]$. O teste para o número $i$ não depende do teste para $i+1$. Esse isolamento mecânico é o paralelismo trivial (embarrassingly parallel).

2. Dissecção linha a linha de tarefa05.c

A Tentativa Ingênua (Race Condition)

int count = 0;
#pragma omp parallel for
for (int i = 2; i <= n; i++) {
    if (is_prime(i)) {
        count++;
    }
}
  • O OpenMP divide os índices e os envia para as threads.
  • O problema está na variável global count. Todas as threads tentam escrever nela ao mesmo tempo. As instruções de leitura e escrita da CPU colidem no barramento de memória.
  • O resultado final é incorreto. De 348.513 primos esperados, o código reporta valores como 81.795. Os incrementos se sobrepõem e desaparecem.

A Solução Correta (Reduction)

int count = 0;
#pragma omp parallel for reduction(+:count)
for (int i = 2; i <= n; i++) {
    if (is_prime(i)) {
        count++;
    }
}
  • O compilador cria uma cópia local de count para cada thread, valendo 0.
  • As threads incrementam a cópia local sem colidir. No fim, o OpenMP soma os subtotais na variável global.

3. Quizzes interativos

Questão 1 de 2
O que é uma Race Condition (condição de corrida) no contexto da programação paralela, como observado no código ingênuo?
Correto! Sem a sincronização (como reduction ou atomic), a operação count++ sofre interrupções e sobreposições nos acessos em memória de baixo nível, causando corrupção do valor global.
Questão 2 de 2
Como a cláusula reduction do OpenMP evita o custo extremo de sincronização global a cada incremento?
Correto! O `reduction` isola a variável, evitando que o tráfego da cache colida repetidamente a cada passo. A integração global acontece apenas uma vez no final do laço.
