Licao sobre listas, critical nomeado e locks

Tarefa 09 com 2 versoes em tarefa09. Tasks, critical nomeado e locks.

1. O problema em 30 segundos

Crie N tasks. Cada task sorteia uma lista e insere um numero no inicio. Sem protecao duas threads leem o mesmo head e uma insercao some. Com critical anonimo a lista 0 bloqueia a lista 1 sem dividir dado.

Voce vai construir 2 programas.

  • V1 usa critical com lista0 e lista1 fixas
  • V2 usa locks com N listas via argv
Por que isso importa
Base teórica (Power Wall e multicore) na Fundamentação teórica. Essa tarefa mostra que dado compartilhado exige lock certo, nem global demais nem ausente.

2. Disseccao linha a linha

V1 com critical nomeado

#pragma omp parallel shared(head0,head1,N) default(none)
{ #pragma omp single
  { for (i=0;i<N;i++) { #pragma omp task firstprivate(i)
    { seed = 12345u + i*2654435761u; qual = rand_r(&seed) % 2;
      if (qual == 0) { #pragma omp critical(lista0)
        inserir(&head0, v); } else { #pragma omp critical(lista1)
        inserir(&head1, v); } } } } }

Single cria N tasks uma vez. Firstprivate copia i por task. Seed por i evita sequencias iguais. Mesmo nome espera junto, nome diferente anda junto.

V2 com locks explicitos

heads = calloc(nlistas, sizeof(No*)); locks = malloc(nlistas*sizeof(omp_lock_t));
for (i=0;i<nlistas;i++) omp_init_lock(&locks[i]);
omp_set_lock(&locks[qual]);
inserir(&heads[qual], v);
omp_unset_lock(&locks[qual]);
for (i=0;i<nlistas;i++) omp_destroy_lock(&locks[i]);

Init uma vez antes, set e unset por insercao, destroy depois. Indices distintos andam juntos. Nome literal nao indexa por variavel, por isso critical nao escala.

3. O que foi medido de verdade

Compile com gcc menos O2 menos fopenmp menos Wall menos lm. Rode com N igual a 50000 e nlistas igual a 8. Cada ponto vale a mediana de 3 repeticoes.

V1 deu c0 igual a 24998 e c1 igual a 25002, total OK em 0,32s. V2 com 8 listas deu total OK em 0,38s. As curvas sobem com threads porque cada insercao paga task mais lock.

4. Quizzes para fixar

Questao 1 de 2
Por que critical com lista0 e lista1 nao se bloqueiam?
Correto. Mesmo nome mesma espera. Nome diferente espera independente.
Questao 2 de 2

Correto. Nome e literal de compilacao. N de execucao pede locks indexaveis.

Fundamentação teórica

Teoria, modelagem matemática e contexto de HPC integrados à prática desta tarefa.

1. Por que a lista quebra no hardware

Inserir no inicio custa dois stores: novo-prox igual a head, depois head igual a novo. Duas threads lendo o mesmo head perdem uma insercao. Esse e o lost update classico de lista encadeada.

Critical sem nome trava tudo num lock global unico, inclusive listas independentes. Critical com nome separa um lock por nome: mesmo nome espera junto, nome diferente anda junto. Com lista0 e lista1 ha dois locks e a insercao numa lista nao bloqueia a outra.

O nome sai resolvido em compilacao e nao aceita variavel como critical com locks de i. Para N definido em execucao foi alocado omp_lock_t locks de N: omp_init_lock antes do paralelo, omp_set_lock e omp_unset_lock por insercao, omp_destroy_lock depois. Tasks criadas com parallel mais single mais task pagam criacao e fila por insercao. A escolha usa rand_r com seed privada por tarefa; rand divide estado global e corre com concorrencia.

Diferenca que importa
Mesmo nome igual a mesma espera. Nome diferente igual a espera independente. N variavel pede vetor de locks, um por posicao.

2. Modelo matematico

Cada insercao paga um malloc mais dois stores mais uma entrada em critical ou lock. Com N igual a 50000 esse custo engole o trabalho util.

$$T(p) \approx N \cdot (c_{task} + c_{sync}(p)) + N \cdot c_{malloc}$$

Speedup segue S de p igual a T de 1 sobre T de p. Amdahl limita pelo trecho serial s.

$$S(p) \le 1/(s+(1-s)/p)$$

Medicao num i7-14700HX: v1 com N igual a 50000 deu c0 igual a 24998 e c1 igual a 25002, total OK em 0,32s. V2 com 8 listas deu total OK em 0,38s. A distribuicao fica perto de N sobre 2 por lista. Com N pequeno as curvas sobem com p porque a sincronizacao domina.

3. Contexto HPC e leitura das duas curvas

V1 com dois nomes isola as listas e mostra o maximo de paralelismo possivel aqui. V2 com vetor de locks mantem o mesmo isolamento para N arbitrario via argv de 2. Em nos NUMA do NPAD a linha disputada pode viajar entre soquetes. Fixar afinidade com OMP_PROC_BIND igual a close e OMP_PLACES igual a cores estabiliza a medida. Esse e o tema da tarefa 13.

Para a defesa
Nome e literal de compilacao e nao indexa. N de execucao pede locks indexaveis. Mostre total igual a N e 24998 contra 25002.
