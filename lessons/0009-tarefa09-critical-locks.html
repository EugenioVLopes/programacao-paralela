Licao sobre listas, critical nomeado e locks

Tarefa 09 com 2 versoes em tarefa09. Tasks, critical nomeado e locks.

1. O problema em 30 segundos

Crie N tasks. Cada task sorteia uma lista e insere um numero no inicio. Sem protecao duas threads leem o mesmo head e uma insercao some. Com critical anonimo a lista 0 bloqueia a lista 1 sem dividir dado.

Voce vai construir 2 programas.

  • V1 usa critical com lista0 e lista1 fixas
  • V2 usa locks com N listas via argv
Por que isso importa
Base teórica (Power Wall e multicore) na Teoria 09. Essa tarefa mostra que dado compartilhado exige lock certo, nem global demais nem ausente.

2. Disseccao linha a linha

V1 com critical nomeado

#pragma omp parallel shared(head0,head1,N) default(none)
{ #pragma omp single
  { for (i=0;i<N;i++) { #pragma omp task firstprivate(i)
    { seed = 12345u + i*2654435761u; qual = rand_r(&seed) % 2;
      if (qual == 0) { #pragma omp critical(lista0)
        inserir(&head0, v); } else { #pragma omp critical(lista1)
        inserir(&head1, v); } } } } }

Single cria N tasks uma vez. Firstprivate copia i por task. Seed por i evita sequencias iguais. Mesmo nome espera junto, nome diferente anda junto.

V2 com locks explicitos

heads = calloc(nlistas, sizeof(No*)); locks = malloc(nlistas*sizeof(omp_lock_t));
for (i=0;i<nlistas;i++) omp_init_lock(&locks[i]);
omp_set_lock(&locks[qual]);
inserir(&heads[qual], v);
omp_unset_lock(&locks[qual]);
for (i=0;i<nlistas;i++) omp_destroy_lock(&locks[i]);

Init uma vez antes, set e unset por insercao, destroy depois. Indices distintos andam juntos. Nome literal nao indexa por variavel, por isso critical nao escala.

3. O que foi medido de verdade

Compile com gcc menos O2 menos fopenmp menos Wall menos lm. Rode com N igual a 50000 e nlistas igual a 8. Cada ponto vale a mediana de 3 repeticoes.

V1 deu c0 igual a 24998 e c1 igual a 25002, total OK em 0,32s. V2 com 8 listas deu total OK em 0,38s. As curvas sobem com threads porque cada insercao paga task mais lock.

4. Quizzes para fixar

Questao 1 de 2
Por que critical com lista0 e lista1 nao se bloqueiam?
Correto. Mesmo nome mesma espera. Nome diferente espera independente.
Questao 2 de 2
Por que o nomeado nao basta para N definido em execucao?
Correto. Nome e literal de compilacao. N de execucao pede locks indexaveis.

5. Fonte primaria e proximos passos

Leia primeiro Pacheco, An Introduction to Parallel Programming, capitulo sobre OpenMP e apendice sobre sincronizacao e locks. Complete com Hennessy e Patterson, parte sobre coerencia e contencao.
  1. Compile v1 e v2 e confira total igual a N com 50000.
  2. Varra nlistas com 2, 8 e 32 e compare os tempos.
  3. Se algo travar, pergunte. Eu detalho critical, locks e tasks.
