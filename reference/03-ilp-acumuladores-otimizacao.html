Referência rápida 03: ILP — Acumuladores e Otimização em C

Guia de consulta rápida para a Tarefa 03 (Paralelismo ao Nível de Instrução)

1. Medição de tempo com clock_gettime

Símbolo / tipo Descrição Valor típico (Linux)
struct timespec Estrutura com tv_sec (segundos) e tv_nsec (nanossegundos) Definido em <time.h>
CLOCK_MONOTONIC Relógio monotônico (não afetado por NTP) Resolução ~1 ns
_POSIX_C_SOURCE 199309L Feature-test macro para habilitar clock_gettime Deve ser definido antes de qualquer #include
clock_gettime() Captura tempo de parede com resolução de nanosegundos Syscall ou vDSO 
#define _POSIX_C_SOURCE 199309L
#include <time.h>

static double agora(void) {
    struct timespec t;
    clock_gettime(CLOCK_MONOTONIC, &t);
    return t.tv_sec + t.tv_nsec / 1e9;
}

double inicio = agora();
/* ... trecho a medir ... */
double tempo = agora() - inicio;
Por que clock_gettime e não clock()?

clock() mede CPU time (soma de todos os núcleos), com resolução de ~1 µs. clock_gettime(CLOCK_MONOTONIC) mede wall time com resolução de ~1 ns. Para programas paralelos (OpenMP), clock() produz resultados enganosos. A Tarefa 03 usa clock_gettime para precisão de nanossegundos.

2. Latência e throughput de instruções

Operação Instrução x86 Latência Throughput rec. Acumuladores ideais
Soma inteira ADD r, r 1 ciclo 0,25 ciclo 4
Soma FP double ADDSD xmm, xmm 4 ciclos 0,5 ciclo 8
Multiplicação FP MULSD xmm, xmm 4 ciclos 0,5 ciclo 8
FMA (mul + add) VFMADD xmm 4 ciclos 0,5 ciclo 8
$$\text{Acumuladores ideais} = \frac{\text{Latência}}{\text{Throughput recíproco}} = \frac{L}{T_r}$$

3. Flags de compilação e seus efeitos

Flag Nível Otimizações relevantes para ILP
-O0 Nenhuma Tradução literal; variáveis na pilha; nenhum unroll
-O1 Básico Promoção a registradores; remoção de código morto
-O2 Padrão Loop unroll parcial; strength reduction; inlining
-O3 Agressivo Auto-vectorização SIMD; unroll agressivo
-march=native — Habilita instruções ISA do hardware local (AVX2, etc.)
-funroll-loops — Força desenrolamento de laços (pode aumentar código) 
# Compilar nos três níveis de otimização:
gcc -std=c11 -Wall -Wextra -O0 tarefa03.c -o tarefa03_O0
gcc -std=c11 -Wall -Wextra -O2 tarefa03.c -o tarefa03_O2
gcc -std=c11 -Wall -Wextra -O3 tarefa03.c -o tarefa03_O3

# Inspecionar o assembly gerado:
gcc -std=c11 -O2 -S tarefa03.c -o tarefa03_O2.s
gcc -std=c11 -O3 -S tarefa03.c -o tarefa03_O3.s

# Verificar se houve vetorização (procurar por vpadd, vpaddd, etc.):
grep -i 'vpadd\|addsd\|paddd' tarefa03_O3.s

4. Padrões de laço para ILP

Acumulador único (cadeia RAW)

long long soma = 0;
for (long i = 0; i < n; ++i)
    soma += v[i];  // cadeia de N dependências

Múltiplos acumuladores (cadeias independentes)

long long s0 = 0, s1 = 0, s2 = 0, s3 = 0;
long i = 0;
for (; i + 3 < n; i += 4) {
    s0 += v[i];
    s1 += v[i + 1];
    s2 += v[i + 2];
    s3 += v[i + 3];
}
/* Tail: elementos restantes */
for (; i < n; ++i) s0 += v[i];
long long soma = s0 + s1 + s2 + s3;
Laço de cauda (tail loop)

Quando $N$ não é divisível por 4, o segundo for processa os últimos 0 a 3 elementos. Isso garante que a soma é correta para qualquer $N$.

5. Resumo executivo de fórmulas

Regras práticas — ILP e acumuladores
  • Acumuladores ideais = $\frac{\text{Latência}}{\text{Throughput recíproco}}$.
  • ADD inteiro: $\frac{1}{0{,}25} = 4$ acumuladores ideais.
  • ADDSD FP double: $\frac{4}{0{,}5} = 8$ acumuladores ideais.
  • Cadeia RAW: $T = N \times L$ ciclos (limitado pela latência).
  • $k$ cadeias independentes: $T \approx \frac{N}{k} \times L$ ciclos.
  • -O0: sem otimização → diferença entre estilos é máxima.
  • -O2/-O3: compilador pode gerar acumuladores e vetorizar → diferença diminui.
  • Use clock_gettime(CLOCK_MONOTONIC) para medição precisa de wall time.
  • Use gcc -S para inspecionar o assembly e confirmar vetorização.
