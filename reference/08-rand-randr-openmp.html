2. Padroes OpenMP da tarefa

O padrao com contador privado soma em variavel local e encosta no total uma vez.

#pragma omp parallel shared(total,N) default(none)
{
  long local = 0;
  #pragma omp for
  for (...) { ... if (x*x+y*y <= 1.0) local++; }
  #pragma omp critical
  total += local;
}

O padrao com vetor escreve em hits por id e soma no serial depois. Eu so uso ele para mostrar o problema.

long *hits = calloc(P, sizeof(long));
#pragma omp parallel shared(hits,N) default(none)
{
  int tid = omp_get_thread_num();
  #pragma omp for
  for (...) { ... if (hit) hits[tid]++; }
}
for (i=0;i<P;i++) total += hits[i];

3. Resumo executivo

Monte Carlo estima pi como 4 vezes N dentro sobre N, com erro perto de 1 sobre raiz de N.

Tempo usa clock_gettime com CLOCK_MONOTONIC e define POSIX_C_SOURCE como 199309L.

Compilo com gcc menos O2 menos fopenmp menos Wall, gero o binario pi e rodo com OMP_NUM_THREADS igual a 1, 2, 4 e 8.

Sao 4 programas. V1 usa critical com rand. V2 usa vetor com rand. V3 usa critical com rand_r. V4 usa vetor com rand_r. Na minha maquina v1 e v2 ficam lentos sem speedup. V3 e rapido com speedup. V4 fica entre v3 e v1 por falso compartilhamento. V4 com pad volta para perto de v3.
