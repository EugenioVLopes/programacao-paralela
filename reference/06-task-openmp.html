Referência 06: Task OpenMP

Folha de consulta rápida para diretivas task, single e taskwait

1. Sintaxe das diretivas

task

#pragma omp task [clause...]
// bloco da tarefa — pode ser único ou composto
{
    // cada tarefa executa este bloco
}

taskwait

#pragma omp taskwait [clause...]

single

#pragma omp single [clause...]
{
    // apenas uma thread executa este bloco
}

2. Cláusulas das diretivas

CláusulaUso emDescrição
shared(list) task Variáveis compartilhadas entre tarefas e threads.
private(list) task Cópia privada não inicializada por tarefa.
firstprivate(list) task Cópia privada inicializada com valor no momento da criação.
depend(type: list) task Dependência entre tarefas (in, out, inout).
priority(value) task Prioridade da tarefa (maior = executada primeiro).
final(expr) task Se expr ≠ 0, tarefas internas executam inline.
nowait single Remove a barreira implícita ao final do bloco.

3. Padrão correto: single + task + taskwait

// Estrutura do nó
typedef struct Node {
    char filename[256];
    struct Node *next;
} Node;

// Travessia: apenas uma thread cria as tarefas
#pragma omp parallel
{
    #pragma omp single
    {
        Node *current = head;
        while (current != NULL) {
            #pragma omp task firstprivate(current)
            {
                printf("Arquivo: %s | Thread: %d\n",
                       current->filename, omp_get_thread_num());
            }
            current = current->next;
        }
    }
    #pragma omp taskwait
}
  • single: apenas uma thread percorre a lista e cria as tarefas.
  • task: cada nó gera uma tarefa.
  • firstprivate(current): cada tarefa recebe o ponteiro do nó com o valor correto no momento da criação.
  • taskwait: aguarda todas as tarefas antes de continuar.

4. Padrão incorreto: laço dentro da região paralela

// ERRADO: todas as threads executam o laço
#pragma omp parallel
{
    Node *current = head;
    while (current != NULL) {
        #pragma omp task
        {
            printf("%s\n", current->filename);
        }
        current = current->next;
    }
}
// Resultado: cada nó processado T vezes (T = número de threads)

5. Funções OpenMP para tasks

FunçãoRetorno
omp_get_thread_num() ID da thread chamadora (0 a omp_get_num_threads()-1)
omp_get_num_threads() Número de threads no time atual
omp_in_parallel() Retorna 1 se dentro de região paralela
omp_get_task_num() ID da tarefa em execução
omp_get_num_tasks() Número de tarefas no team atual

7. Mapeamento: tarefa por nó da lista

Cada nó da lista gera exatamente uma tarefa. O runtime distribui entre as threads disponíveis.

NóTarefa criadaThread que executa
node 1task_1variável (work-stealing)
node 2task_2variável (work-stealing)
node 3task_3variável (work-stealing)
...

A thread que executa cada tarefa é determinada pelo scheduler em tempo de execução — não é determinística.

8. Quiz rápido

1. Por que o single é necessário no padrão correto?

  1. Para dividir o laço entre as threads
  2. Para garantir que apenas uma thread percorra a lista e crie as tarefas
  3. Para acelerar o acesso à lista encadeada

2. O que acontece se o laço de travessia estiver dentro da região paralela, sem single?

  1. Cada nó é processado exatamente uma vez
  2. Cada nó é processado múltiplas vezes (T vezes)
  3. O programa para de executar

3. Para que serve o taskwait?

  1. Para criar mais tarefas
  2. Para aguardar que todas as tarefas criadas no bloco atual terminem
  3. Para definir a prioridade das tarefas
