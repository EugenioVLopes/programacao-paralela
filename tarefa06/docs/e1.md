# Etapa 1 — Respostas

## 9. O que cada parte de `#pragma omp parallel for` faz

`parallel` cria um time de threads. Cada thread executa o bloco inteiro que vem depois. `for` distribui as iterações do laço entre as threads que já existem.

Quando separados, você pode ter código que roda uma vez por thread (fora do `for`) e código que roda uma vez por iteração (dentro do `for`).

## 10. Observação da inconsistência

```bash
OMP_NUM_THREADS=8 for i in 1 2 3 4 5; do ./e1; done
```

O valor de `dentro_circulo` (e portanto de π) muda entre execuções. Às vezes dá 3.14, às vezes 2.9, às vezes 3.5. O comportamento é imprevisível.

## 11. Hipótese sobre a causa

A linha `dentro_circulo++` não é atômica. Na verdade são várias instruções de máquina: ler o valor da memória em um registrador, somar 1, escrever o registrador de volta.

Se duas threads executam essas instruções ao mesmo tempo, elas podem ler o mesmo valor antes de escrever, e uma sobrescreve a outra. Resultado: increments são perdidos. É uma condição de corrida clássica.

O fato de `rand_r()` ser thread-safe (cada thread com sua seed) não impede o problema. A corrida não é no gerador de números, é no contador compartilhado.

## 12. Programa mínimo (desafio opcional)

```c
#include <omp.h>
#include <stdio.h>

int main() {
    long long contador = 0;
    #pragma omp parallel for
    for (long long i = 0; i < 100000000LL; i++) {
        contador++;
    }
    printf("contador = %lld\n", contador);
    return 0;
}
```

Compilado com `-O0`, o bug aparece mais porque o compilador não otimiza as instruções, deixando a corrida mais evidente.
