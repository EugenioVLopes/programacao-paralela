# Etapa 4 — Respostas

## 24. Comportamento de `private(x)`

```c
int x = 100;
#pragma omp parallel for private(x)
for (int i = 0; i < 8; i++) {
    printf("Thread %d: x = %d\n", omp_get_thread_num(), x);
    x = omp_get_thread_num();
}
printf("Fora: x = %d\n", x);
```

Antes de rodar, a previsão é que x não valha 100 dentro do laço. `private(x)` cria uma cópia não inicializada para cada thread. O valor de x dentro do laço é lixo de memória (ou o valor que outra thread deixou naquela posição). Fora da região paralela, x continua 100 porque a variável original não é modificada.

Saída observada:

```
Thread 4: x = 8          // valor indefinido
Thread 7: x = 1538389742 // lixo de memória
Thread 0: x = 0          // aconteceu de ser 0
Fora: x = 100
```

## 25. Comportamento de `firstprivate(x)`

```c
int x = 100;
#pragma omp parallel for firstprivate(x)
for (int i = 0; i < 8; i++) {
    printf("Thread %d: x = %d\n", omp_get_thread_num(), x);
    x = omp_get_thread_num();
}
printf("Fora: x = %d\n", x);
```

A diferença é que `firstprivate` inicializa cada cópia com o valor original. Todas as threads veem x = 100 antes de atribuir qualquer coisa. Fora da região paralela, x continua 100, igual ao caso anterior.

Saída observada:

```
Thread 6: x = 100
Thread 3: x = 100
Thread 0: x = 100
Fora: x = 100
```

## 26. Valor de `x` fora da região paralela

Em ambos os casos (`private` e `firstprivate`), x fora da região paralela continua 100. Nenhuma das duas cláusulas modifica a variável original. O que acontece dentro do `parallel` fica dentro do `parallel`.

## 27. Comportamento de `lastprivate`

```c
int resultado = 0;
#pragma omp parallel for lastprivate(resultado)
for (int i = 0; i < 20; i++) {
    resultado = i * i;
}
printf("resultado = %d (esperado: %d)\n", resultado, 19 * 19);
```

`lastprivate` atribui à variável o valor da última iteração (i = N-1 = 19). Independente de qual thread executa essa iteração, o resultado é sempre 361 (19²). Rodando várias vezes, o valor impresso é sempre 361, confirmando que o comportamento é determinístico.

## 28. `default(none)` com variável não classificada

```c
int x = 10, y = 20, soma = 0;
#pragma omp parallel for default(none) shared(x, soma)
for (int i = 0; i < 10; i++) {
    soma += x + y;  // y não está classificada!
}
```

Tentar compilar produz:

```
error: 'y' not specified in enclosing 'parallel'
```

A mensagem indica o nome exato da variável (`y`) e a linha onde ela é usada sem classificação. É assim que `default(none)` funciona: força o programador a pensar em cada variável e classificá-la explicitamente, evitando erros silenciosos como compartilhamento acidental ou esquecimento de escopo.
